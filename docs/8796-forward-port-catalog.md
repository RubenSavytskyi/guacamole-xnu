# XNU 8796 patch inventory for forward-port to XNU 12377.121.6

[перевірено] `ios-guacamole/xnu/patches` має 214 файлів: 211 `.patch` та 3 staging `.sh`; однакові номери для скриптів/патчів лишаються окремими рядками.

[перевірено] Аналог звірено з локальними `guacamole-xnu/patches/0001–0019`. «Частково» означає спільний шар, не тотожний код; 0015–0019 тут переважно діагностичні зміни.

[припущення] Висновок «до launchd» залежить від вибраного root і конфігурації AMFI; це оцінка ролі патча, а не доказ повного завантаження 8796 userland. Tahoe firstboot payload не має root/ufsroot аргументу.

## Follow-up: 0020 readiness, ISA, runtime limits

[перевірено] `tools/nopac/tests/isatest.py` запущено локально, але воно завершилось `FileNotFoundError: [WinError 2]` під час запуску `clang`; Windows checkout не має `clang` у PATH. Це не результат ISA-перевірки ядра й не PASS. Потрібно виконати `python3 tools/nopac/nopac_rewrite.py --macho --isa-report kernel.development.sweet.link/<DWARF kernel>` на macOS runner, де доступні clang/llvm tools та unstripped kernel. У збереженому артефакті `.dSYM` DWARF ядра відсутній, хоча build metadata лежить поруч.

[перевірено] Статичне сканування інструкцій не знаходить MMIO через звичайні load/store до фізичних адрес Apple-блоків, якщо ці адреси не зашиті як впізнавані константи; воно також не визначає доступність вузла/регіону в конкретному ADT і не доводить, що шлях виконався.

[припущення] Для runtime-виявлення на першому boot додати ранні framebuffer breadcrumbs перед/після кожного доступу до важливого MMIO-блоку та аварійно оброблювати external abort з ESR_EL1/FAR_EL1 у sync exception path; друкувати FAR, ESR і поточний етап у framebuffer. Додатково створити SWEET ADT-профіль без Apple-only вузлів і властивостей та перевіряти, що PE/драйвери пропускають їх за відсутності вузлів. Саме вилучення вузлів без abort diagnostics не гарантує виявлення raw-MMIO доступів.

[перевірено] Патч 0020 поки не сформовано: `CONFIG_CPU_COUNTERS` у XNU 12377 обирає компоненти через `config/MASTER.arm64` і `osfmk/conf/files.arm64`; його відключення має бути зроблене на рівні вибору компонентів для SWEET, а просте `cpc_cpmu_supported=false` лишає інструкції у binary. Без перевіреного механізму SWEET-специфічного вибору не можна заявляти 0 CRn=15 для групи (a). `git apply --check` для 0020, відповідно, ще не виконано.
